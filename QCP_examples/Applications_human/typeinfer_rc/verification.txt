Representation and ownership

  M is a mathematical map, not an additional runtime data structure.
  nodes maps addresses to one-layer payloads; children is a list of owning
  edges, so duplicate child addresses contribute multiple references.
  counts = roots + incoming-edge multiplicity, with 0 <= reserved <= roots.
  Live nodes have positive bounded counts; the graph is finite, closed and
  acyclic. Finite support is existential in Prop, not a stored Live_keys list.

  store_type M p tr is the pure decode relation. It does not own memory or
  grant a release credit. store_world M owns each live node's fields once,
  and ties its physical refcnt to counts M p. store_solution M res s owns
  the 100 pointer slots, relates their addresses to mathematical types,
  and bounds pointer multiplicity by roots - reserved. It does not own
  the pointed-to nodes. The top-level heap is world ** solution.

  retain increments roots/counts/reserved. publish transfers one reserved
  credit to a container without changing the physical count. A non-final
  release decrements all three. Deleting a final-reference parent converts
  its outgoing edges into reserved child roots before recursive release;
  this supports shared children and repeated edges.

  This demo uses centralized world ownership and one solution container,
  not fractional permissions, an STS, or independently composable linear
  handle tokens. Multiple containers require combined accounting or a
  further ownership interface. Arbitrary syntax-tree insertion/update and
  expression matching are not claimed to be completed here.

Mathematical specification and trust boundary

  The original TypeTree, sol, unify_rel, sol_correct_iter, sol_compress_to
  and sound_pv.unify_soundness are reused, not weakened or redefined.
  Actual successful C returns establish the original unify_rel. The
  same_return_final_bridge__final_compression helper uses the original
  soundness theorem for that same return value and supplies the compressed
  solution conclusion. Failure retains a valid solution; borrowed input
  nodes and their decoding are preserved.

  rc_capacity excludes overflow in the execution model; it does not
  assume heap safety or mathematical correctness.
  The bodies of copy_atype, free_atype and the three unify stages are
  verified. get_map, add_map, type_var_occur, atype_repr and the raw
  free_atype_node allocator boundary are external contracts in this demo.

  Manual and case-library proofs contain no Admitted or added Axiom.
  However, proof_auto contains 153 generator-emitted Admitted placeholders
  for native automatically discharged obligations, as in the original
  workflow. Manual/helpers do not rely on those placeholders. This is
  not an axiom-free end-to-end kernel certificate.

  Windows, from the repository root:
    .\dune.cmd build Rocq/examples/Applications_human/typeinfer_rc/typeinfer_rc_goal_check.vo
  Other supported Dune environments, from the repository root:
    dune build Rocq/examples/Applications_human/typeinfer_rc/typeinfer_rc_goal_check.vo
  GNU Make, with the repository's configured Coq environment:
    make -C Rocq examples/Applications_human/typeinfer_rc/typeinfer_rc_goal_check.vo

  Rocq/Makefile includes the instance, function and strategy modules. The Applications_human
  Dune theory includes typeinfer_rc. Both run-example-linux.sh and
  run-example-windows.cmd include its symexec generation entry. There is
  a case-specific typeinfer_rc.strategies file with certificates depending
  on the reusable typeinfer_rc instance, not the VC helper lib. The collection script discovers the
  C source recursively. No Lean port is claimed.

  Generation is not proof checking and may update generated files. Use
  the verification-orchestrator workflow in AGENTS.md for verification
  changes; do not treat running an example generator as a completed proof.
