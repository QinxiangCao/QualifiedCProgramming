## Status definitions

- `intentional`: an unavoidable representation or host-language mechanism difference whose observable source semantics are preserved.
- `open`: a difference that may require a later compatibility improvement.
- `resolved`: a previously observed difference that now has an equivalent compatibility layer.
- `source-risk`: suspicious source behavior intentionally preserved; it is not a Coq/Lean semantic difference.

## Tactic parity policy

Every migrated Coq tactic must be accepted by branch-level functional parity, not by a representative smoke test alone.

1. Inventory every public tactic, its invocation syntax, ordered match/rewrite branches, recursive/progress behavior, side-condition solver, terminal closure branches, no-match behavior, and deliberately observable failure cases.
2. Preserve every source success case used by a branch, the resulting normalized goal or closed proof, the source branch priority whenever overlapping patterns can change the result, and no-op versus hard-failure behavior where the host tactic API permits it.
3. Add at least one Lean regression test for every source branch, plus tests for recursive/nested normalization, terminal closure, no-match behavior, and any failure used by tactic combinators. A single representative downstream proof is not sufficient evidence.
4. If Lean cannot reproduce an Ltac parser, trace, generated hypothesis name, backtracking point, or exact failure boundary, record the smallest remaining difference in this document before the tactic migration is accepted. State whether Lean accepts fewer or more goals and whether that can affect downstream branch selection.
5. Do not claim tactic parity while an original successful branch is missing. A broader Lean success domain is allowed only when it is harmless, explicitly documented, and tested; prefer narrowing it when practical.
