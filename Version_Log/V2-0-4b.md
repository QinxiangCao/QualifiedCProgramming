# V2.0.4b binary 更新后的 proof port 指引

本文记录本次 binary 更新后，AI 在迁移既有 proof 时应优先检查的事项。当前观察到的主要变化不是 VC 语义被重写，而是 branch/order 变化导致相邻 witness 名称与原 proof body 的对应关系漂移。

## 核心判断

当旧 proof 在新生成的 `*_goal.v` 下失败，尤其报告：

```text
Attempt to save an incomplete proof
Cannot find any non-recursive equality over ...
The term ... has type ... while it is expected to have type ...
```

不要马上重新证明。先比较新旧 `*_goal.v` 中失败 witness 的前提、分支条件和 postcondition。如果两个或多个相邻 VC 只是顺序交换，通常直接交换 VC 名字对应的 proof body，或在保持 lemma 名字不变的前提下交换 proof body 即可。

## 推荐 port 流程

1. 先确认生成命令和 logical path 正确，特别是 `-I` 与 `-slp`。同名 strategy/lib 同时存在时，必须让物理路径和 Rocq logical path 成对出现。
2. 对失败 witness 建立语义映射，不按 `..._wit_1_1` / `..._wit_1_2` 的编号机械匹配旧 proof。
3. 对比关键 discriminator，例如 `x = 0` 与 `y = 0`、`retval < retval_2` 与 `retval >= retval_2`、以及 existential witness 的顺序。
4. 如果只是相邻 branch 交换，优先交换 proof body；必要时微调 `Exists` 顺序或移动 `perm_swap` 这类与空间资源顺序相关的步骤。
5. 对三分支或四分支 witness，先写出 old-to-current 映射再改名，避免只交换相邻两个后引入二次错位。
6. 先跑最小 Coq target，例如单个 `*_proof_manual_partN.vo` 或单个 `*_goal_check.vo`；通过后再跑完整 changed target 列表。
7. 如果 import path 或 Makefile example 列表变化，先刷新 dependency shard，再做 proof check。

## `goal_check` 中 label already declared 的处理

如果 `*_goal_check.v` 报：

```text
The label proof_of_xxx is already declared.
```

优先判断为 `*_proof_auto.v` 与 `*_proof_manual.v` 同时提供了同名 `Lemma`，而不是 VC 本身不可证。修复顺序：

1. 不修改 `*_proof_auto.v`。先比较 manual/auto 中的 `^Lemma proof_of_...` 名称交集，找出重复 label。
2. 再比较 `*_goal.v` 的 `^Axiom proof_of_...` 与 manual+auto 的并集，找出缺失 label。
3. 如果重复 label 正好与缺失 label 位于同一组相邻 branch，例如 auto 已有 `_7_2` 而 manual 也写了 `_7_2`，同时缺 `_7_1`，通常是 manual proof body 绑定到了错误分支，应把 manual lemma 改名/改 unfold 到缺失 witness，而不是删除 proof body。
4. 如果重复 label 在 auto 中已有，且删除 manual 中该 lemma 后 manual+auto 仍覆盖所有 `VC_Correct` axiom，则直接删除 manual 里的重复 lemma。典型情况是简单 wrapper/return witness 被 auto 已经解决。
5. 每次修改后先静态确认：manual/auto 交集为空，`goal.v` axiom 没有缺失；然后跑 `*_goal_check.vo`。

Windows/PowerShell 下 `mingw32-make` 有时第一次只打印 `COQC ...` 就退出，不给 Coq diagnostic；可单独重跑同一 `.vo` target 取更具体错误。某些大 manual 文件本身重编很慢，不要把 3-5 分钟误判成死循环；如果怀疑是 `lia`/`nia` 长跑，优先把对应 VC 拆成小 assert 或 split-goal 单独证明。
